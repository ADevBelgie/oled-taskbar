# OLED Taskbar

![OLED Taskbar icon](assets/oled-taskbar.png)

Move the **real Windows taskbar** to the secondary monitor while keeping your
primary OLED display primary and its entire desktop area usable. The system tray
is Windows' own tray, not a reimplementation.

## Scope and safety

This is an experimental Windows 11 x64 utility for **exactly two monitors**. It
selects the non-primary display automatically; no monitor brand, serial number,
or hardware ID is compiled into the public version.

The native bridge uses undocumented Windows shell functions and checks the local
taskbar image identity against matching symbols. Symbol validation is not a
guarantee of compatibility: a Windows update can change behavior and require code
changes. Unsupported or failed layouts trigger restoration rather than acceptance
of a partial layout. Keep work saved before first testing it.

No Windhawk, separate .NET runtime, driver, or third-party background app is
required. The app uses Windows' existing .NET Framework and system libraries, plus
a small statically bundled MinHook component. **Building from source** requires an
already-installed MSVC x64 C++ toolchain and Windows SDK; scripts install nothing.

## Build and install

From PowerShell in the repository:

```powershell
.\build.ps1
.\test-v2.ps1
.\prepare-symbols.ps1
.\install-v2.ps1
```

Symbol preparation downloads matching public Windows debug symbols from Microsoft
and generates a local, Git-ignored `dist\bridge.ini`. No prepared system-specific
configuration or compiled executable is shipped in this source repository.

After installation, search Windows for **OLED Taskbar**. The panel provides Enable,
Disable / restore, Start with Windows, Uninstall, and Exit and restore. Closing the
window hides the panel; it does not disable the utility. Separate Enable, Disable,
and Uninstall Start Menu shortcuts are also created. Startup is opt-in.

Disable restores the saved auto-hide preference and native taskbar placement.
The normal multi-monitor taskbar preference is left unchanged. The bridge watches
the controller's process handle and restores the layout if that process exits.
There is no steady-state polling loop or per-frame hook in game processes.

When only one display is connected, for example while the primary monitor is
switched off, there is nowhere to move the taskbar. OLED Taskbar restores
Windows' own layout once, waits quietly, and re-enables when the second display
returns and Explorer has rebuilt its taskbar.

## After Windows updates

Windows updates regularly replace `taskbar.dll`. The saved symbols then no longer
match, and the bridge refuses to hook Explorer instead of guessing addresses.
OLED Taskbar detects this before changing anything: startup leaves Windows'
original taskbar in place and shows a message, and pressing **Enable** asks to
download the matching public symbols from Microsoft and refreshes the installed
`bridge.ini`. No rebuild, reinstall, or sign-out is needed. If Microsoft has no
matching symbols for the new build, the utility stays disabled.

## Uninstall and upgrades

Use the panel's Uninstall button, the Uninstall OLED Taskbar shortcut, or Windows'
installed-app list. Restoration is checked before removal. The inactive bridge
can remain loaded until sign-out; deferred cleanup removes locked files at next
sign-in. Local diagnostic logs are retained so you can inspect failures.

Upgrades require disabling/exiting the app and signing out to unload its native
bridge. The installer refuses to stack native bridge versions in shell processes.

## Verification and limitations

The original two-display implementation was exercised with repeated enable/disable
cycles, standard maximized-window bounds, forced controller-exit restoration, and
startup-mode reapplication. Its user confirmed the layout and native taskbar
functionality. The public generalized display-selection variant is build- and
geometry-test validated, not certified across all hardware and Windows builds.

Full reboot, display hotplug, and every game/anti-cheat combination are not claimed
as tested. Run `dist\NativeControl.exe probe` for local diagnostics;
`test-workarea` briefly creates the utility's own test windows on each display.
Review diagnostic output before sharing it.

## Privacy and license
